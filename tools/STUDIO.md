# Автоматизированная студия

Windows, Python 3.10+ и сборка FFmpeg с libass, libx264, AAC и ffprobe в PATH. Запуск из корня репозитория.

```powershell
python tools/studio.py 001                      # dry-run, стоимость и недостающие настройки
python tools/studio.py 001 --synthetic --run    # бесплатный сквозной тест, без исходников проекта
python tools/studio.py 001 --max-shots 3 --run  # реальный короткий пилот после настройки
python tools/studio.py 001 --run                # глава целиком, до 24 планов по умолчанию
python tools/studio_gui.py                     # необязательно, те же команды через Tkinter
```

Повтор той же команды возобновляет сборку. Папка `output/studio/` содержит сценарий и раскадровку, файлы озвучки и панелей, SRT, `episode.mp4`, обложку `thumbnail.jpg`, метаданные `youtube.json`, `report.json` и журнал `journal.jsonl`. Манифест подтверждает хеши результатов. Успешные этапы повторно используются, испорченные пересобираются. Изменение исходников, версии кода, выбранных настроек или числа планов создаёт новую сборку. Задания ComfyUI сохраняют ID, чтобы после таймаута проверять то же задание. Ожидание ограничено, повторов не больше двух на этап. Офлайн-генерация и ручная публикация. Платёжный лимит жёстко равен 0 USD, API подписок не используются.

## Локальные источники и адаптеры

Скопируйте `.env.example` в локальный `.env`. Путь `STUDIO_REFERENCE` указывает на утверждённый PNG концепта Джинхёка. Пробные рисунки не следует назначать эталоном. Оркестратор читает только полную главу `chapters/NNN.md` и файлы лора и канона. Конспект 002 остаётся конспектом.

- **Текст — Ollama.** Запустите Ollama с отключённым облаком (`OLLAMA_NO_CLOUD=1`) и укажите установленную локальную модель. Генерация возвращает JSON. Проверяемые цитаты должны идти в исходном порядке и дословно присутствовать в главе. Необязательный `STUDIO_VISION_MODEL` оценивает соответствие панелей, персонажей и содержания иллюстраций. Выбирайте локальную модель с поддержкой нескольких изображений и проверяйте её оценки перед выпуском. [Ollama Generate](https://docs.ollama.com/api/generate) · [Офлайн-настройка](https://docs.ollama.com/faq#how-do-i-disable-ollamas-cloud-features)
- **Кадры — ComfyUI.** Экспортируйте проверенную локальную схему в API JSON. В нужных полях входов укажите строковые маркеры `$PROMPT` (положительный текст), `$REFERENCE` (поле имени изображения у LoadImage) и `$SEED` (seed). Подключите выход LoadImage к ветви реального кондиционирования референсом и укажите ID SaveImage в `STUDIO_COMFY_OUTPUT_NODE`. Используйте один локальный граф с batch size 1. Облачные узлы отклоняются. Для проверенных сторонних узлов укажите их `class_type` через запятую в `STUDIO_COMFY_TRUSTED_NODES`. Пользуйтесь доверенной локальной установкой ComfyUI. [Маршруты ComfyUI](https://docs.comfy.org/development/comfyui-server/comms_routes)
- **Озвучка — Piper.** Укажите один локальный файл голоса `.onnx` с соседним `.onnx.json`. По умолчанию используется `python -m piper` из того же окружения. `STUDIO_PIPER_EXECUTABLE` может указывать на совместимый CLI. Один голос используется последовательно для всех планов главы. [Piper CLI](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/CLI.md)
- **Готовые локальные материалы — prepared.** Для любого из трёх этапов можно указать `prepared` вместо провайдера. В каталоге `STUDIO_PREPARED_DIR` положите `plan.json`, `panel-001.png`, `voice-001.wav` и дальнейшие файлы по номеру плана для выбранного этапа. Структура плана описана ниже. Это позволяет заменить генератор одного этапа или собрать выпуск из уже проверенных материалов.

Для RTX 5060 Laptop с примерно 8 ГБ VRAM разумно начать с локальной текстовой модели класса 3–4B с 4-битным квантованием и малопамятного графа для иллюстраций, по одному кадру за раз. Piper запускается на CPU. Ollama выгружает модель между запросами, чтобы освободить VRAM для ComfyUI. Подберите лицензированные для коммерческого использования веса и голос. Студия сама ничего не устанавливает и не скачивает.

## Формат плана и проверка

JSON содержит `title`, `description`, `tags`, номер `cover_shot` с 1 и массив `shots`. У каждого плана есть `camera` (`static`, `push`, `pull`, `pan`), `characters` (список строк), `image_prompt`, `narration` и `source_quote` (цитата на языке главы). Субтитры делятся на короткие реплики, таймкоды внутри каждого плана приблизительные, а его общая длительность привязана к аудио.

Проверки покрывают порядок опорных цитат, написание имён, отсутствие побайтовых дублей, декодирование панелей и MP4, уровень звука, порядок и длительность субтитров. Модельная проверка внешности и редакторская проверка сюжета дополняют эти сигналы. Хеши и точные цитаты сами по себе не подтверждают художественную непрерывность и точность пересказа. Даже при `pass` видео остаётся черновиком на утверждение.

```powershell
python tools/test_studio.py

```
