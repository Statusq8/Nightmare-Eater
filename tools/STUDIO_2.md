# Nightmare Eater Studio 2.0

Студия хранит данные всех глав в одной локальной базе. Статус обработки выдаётся отдельно от статуса готовности выпуска. Видео остаются локальными до решения владельца.

## Как устроено производство

1. Ввод главы сохраняет полный текст и его SHA‑256. Один номер главы связан с одной версией исходника. Идентификаторы объектов сохраняются между главами и разрешаются через псевдонимы.
2. Сцены содержат точные границы исходного текста, события звукового плана и состояние объектов на момент сцены. Для 001 отдельные текстовые переходы фиксируют квартиру, палату, коридор и операционную. Обычное упоминание локации не перекидывает действие в неё внутри этой главы.
3. SQLite хранит персонажей, аномалии, локации, предметы, Систему и голосовые роли. Свойства версионируются по номеру главы и положению в исходнике. Модельные изменения остаются предложениями с цитатой. Прямо названные вещи можно зарегистрировать по однозначному текстовому свидетельству. Размеры, расположение и внешность остаются неопределёнными там, где оригинал их не задаёт.
4. Библиотека сохраняет ассеты по хешу и версии. Профиль палаты содержит относительную географию из визуального пилота как проектное предложение. Файл прилагает к кадрам один и тот же ориентир и указывает, что наличие окна в двери не задано текстом. Утверждённый лист Джинхёка зафиксирован как исходник. Запросы недостающих ракурсов используют уже зарегистрированные версии.
5. Локальный Ollama-адаптер принимает структурированный контекст сцены. Его ответ проверяется по последовательным цитатам и полному покрытию реплик. Перевод EN, эмоциональная игра, каждого нового персонажа и геометрию нельзя утвердить только по структурной проверке ответа.
6. Монтаж требует отдельного QA-отчёта на подготовленные сцены. Отчёт привязан к хешам медиа и утверждённым референсам. Ритм следует длительности более длинной версии диалога и минимальным паузам. Поддерживаются статичный кадр, мягкое приближение и плавное движение. Пропорции 40/30/20/10 остаются художественным ориентиром. Параллакс отключён в основном сборщике до испытаний на разрывы краёв.
7. Мастер содержит один видеоряд и переключаемые дорожки RU/EN. Отдельно экспортируются WAV диалога, общих музыки, окружения и фоли, финальные миксы, SRT/VTT и локализованные метаданные. Ассеты звука допускаются после указания источника, лицензии и разрешения на коммерческое использование.

## Режимы и команды

Из корня проекта, Windows, Python 3.12, FFmpeg и ffprobe в PATH. Глава 001 лежит в `chapters/001.md`.

```powershell
python tools/studio2.py enqueue 1 chapters/001.md
python tools/studio2.py work --drain
python tools/studio2.py status
python tools/studio2.py backup output/studio2-2026-11-26-backup.zip
```

`plan` составляет план и список запросов референсов локально. `direct` вызывает уже установленную текстовую модель Ollama. `references` генерирует ограниченную партию кандидатов через ComfyUI. `prepared` принимает отсмотренные медиа и формирует двуязычный мастер. `fixture` генерирует цветовые поля и тестовые тоны для диагностики сборки. Эти прогоны не являются сериями.

```powershell
python tools/studio2.py enqueue 1 chapters/001.md --mode direct
python tools/studio2.py work --chapter 1 --mode direct --start-ollama --drain
python tools/studio2.py references 1 --entity 'Палата' --limit 1 --start-comfy

python tools/studio2.py enqueue 1 chapters/001.md --mode fixture
python tools/studio2.py work --chapter 1 --mode fixture
python tools/studio2.py work --chapter 1 --mode fixture --rerender-scene 2
python tools/test_studio2.py
```

Один экземпляр worker берёт задания по номеру главы. После сбоя прерванный запуск возвращается в очередь. Ошибки сохраняются. Две неудачные попытки блокируют задание до устранения причины и явного повторного запуска. Перерендер сцены инвалидирует её видеоэтап и сохраняет остальные сценовые MP4 в кэше. Финальный монтаж и звуковой микс обновляются. Резервная копия включает согласованный снимок SQLite и все зарегистрированные файлы, с проверкой хешей. Исходники и прошлые пилоты остаются отдельно. Резервный архив можно развернуть в новом каталоге, приняв его за `--home`. SQLite используется локально, а не в общей сетевой папке.

## Контракт подготовленных сцен

Каталог `output/studio2/prepared/001/scene-001/` содержит картинки, `ru.wav`, `en.wav` и `review.json`. В отчёте указываются `chapter_sha`, `scene`, `reviewer`, хеши файлов в `files`, карта `references` из UUID сущностей в хеши использованных утверждённых ассетов, `camera`, `visual` с полями `identity, layout, anatomy, style, motion`, `speech.ru` и `speech.en` с `words, voice_identity, performance`. Положительные флаги выдаёт отдельный проверяющий процесс. Для одной картинки используется `panel.png`. Для нескольких планов задаётся массив `shots`, где у каждого объекта есть `file` вида `shot-001.png`, `frames`, `camera` и проверка `visual`. Общая длительность должна покрывать обе дорожки и паузу. `captions.ru/en` содержат массивы `{start, end, text}` с локальными номерами кадров. RU-текст сверяется с исходником. В корне главы лежат `music.wav`, `ambience.wav`, `effects.wav`, `credits.json` и двуязычный `youtube.json`.

## Модели и ноутбук

- Образец цвета и пластики взят из последнего 30-секундного пилота. Точные веса и seed управляемого ImageGen не раскрыты. Файлы раскадровки и результат последнего прогона сохранены.
- Доступные локальные веса SDXL и IP-Adapter дают отдельные кандидаты по референсу. ControlNet для геометрии и LoRA для стиля остаются сменными расширениями. Проверенных весов для них на ноутбуке нет. Для калибровки сравнивать одни и те же комнатные ракурсы и фиксировать позицию двери, наличие окна и порядок предметов. [IP-Adapter](https://github.com/cubiq/ComfyUI_IPAdapter_plus)
- Предыдущий прогон сравнил Piper, Windows SAPI и VoxCPM2. Локальный VoxCPM2 подключён к реестру для двух языков и использует один закреплённый WAV для каждой пары роли и языка. Голоса, перенесённые из двуязычного пилота, имеют статус кандидатов. Долговременная стабильность звучания и отдельные голоса всех персонажей полной главы ещё требуют проверки. [VoxCPM2](https://github.com/OpenBMB/VoxCPM)
- На RTX 5060 Laptop с 8 ГБ VRAM генерацию изображений и речи запускать последовательно. FFmpeg и SQLite работают на CPU. Платный бюджет зафиксирован на нуле. Уровень нагрузки и длительность каждой полной главы предстоит измерить на реальном прогоне.

## Граница текущего релиза

Работают память, постановка в очередь, инспекция, резервная копия, кандидаты визуальных референсов, привязка голосов, сквозной тест мастера и контракт передачи проверенных сцен. Для полной автономии требуются откалиброванный локальный режиссёр, замкнутый цикл независимой художественной проверки и повторной генерации, автоматизация подготовки многоплановых сцен и поставка лицензированных звуковых дорожек. Технический отчёт никогда не разрешает публикацию.
