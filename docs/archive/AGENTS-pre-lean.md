# ОБЯЗАТЕЛЬНЫЙ ШЛЮЗ ПЕРЕД НАЧАЛОМ ЛЮБОЙ РАБОТЫ
Перед каждой задачей, продолжением, подзадачей или переходом этапа ОБЯЗАТЕЛЬНО прочитать актуальный [MASTER_RULES.md](https://github.com/Statusq8/Nightmare-Eater/blob/main/MASTER_RULES.md) из main целиком, PROJECT_MEMORY.md и применимые утверждённые референсы. MASTER_RULES.md обязателен для всех ИИ, агентов, инструментов и веток. Не начинать зависимое производство, пока не проверены эталоны и их статусы. При отсутствии, недоступности или конфликте правил/эталонов остановить зависимый этап и сообщить блокер; не выдумывать замену. Разрешена подготовка черновиков для утверждения. Записывать применимые правила, версии эталонов и результаты проверок в PROGRESS.md. Перед сдачей повторно проверить соответствие регламенту. Не обходить требования делегированием. Не изменять регламент без явного разрешения владельца. При конфликте со старыми инструкциями запросить решение владельца. Не заявлять о выполнении без фактической проверки.
 
# Инструкции для Codex
Проект: авторская хоррор-манхва «Пожиратель кошмаров», адаптация для YouTube.
Перед работой прочитай README.md, lore/story-bible.md, lore/character-design.md, TASKS.md и PROGRESS.md. Главы и утверждённый визуальный канон не изменяй без согласования. Черновики лора не считай окончательными. Не выдумывай отсутствующие исходники. Актуальные тексты глав лежат в `chapters/`, утверждённые референсы и ограничения указаны в памяти проекта.
Работай только в Nightmare-Eater. Не публикуй видео, не покупай услуги, не передавай секреты и не меняй видимость репозитория без явного разрешения. Не добавляй ключи API в git.
Выполняй задачи из TASKS.md, проверяй результаты, отмечай статус и записывай изменения, команды проверки и блокеры в PROGRESS.md. Новые инструменты должны поддерживать Windows и локальный запуск; по возможности бесплатные. Не перезаписывай пользовательские ассеты. Не выдавай черновой текст за утверждённый.

## Память проекта
Перед новой задачей прочитай [PROJECT_MEMORY.md в main](https://github.com/Statusq8/Nightmare-Eater/blob/main/PROJECT_MEMORY.md). После содержательного обсуждения или завершённого этапа обнови этот файл в `main`: зафиксируй решения, результаты проверки, блокеры и следующий шаг. Технические подробности по-прежнему записывай в `PROGRESS.md` соответствующей ветки.
