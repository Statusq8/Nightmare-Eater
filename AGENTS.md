# Nightmare-Eater — Lean Mode (обязательно)
Работать только в Statusq8/Nightmare-Eater. Цель: качественная читаемая хоррор-манхва, не разработка студии.
## Старт
- Прочитай этот файл и CURRENT_STATE.md один раз на задачу; повторно только при изменении.
- Загружай один подходящий Skill из .agents/skills/ по задаче, остальные только при необходимости.
- Читай точный фрагмент главы, нужные паспорта и применимые разделы MASTER_RULES.md. Полный регламент — при конфликте, неопределённости, изменении правил или финальной проверке выпуска.
- Не перечитывай весь репозиторий, историю, PROJECT_MEMORY.md или PROGRESS.md без конкретной причины. Используй поиск по нужным ID/разделам.
## Неприкосновенные требования
- Главы, канон, утверждённые эталоны неизменны. Не добавлять, не удалять, не переставлять события и реплики. Каждая панель привязана к источнику.
- Проверяй наличие и статус оригинальных референсов; если недоступны, останови зависимый этап. Не заменяй их догадками. Черновики допустимы только как REVIEW.
- Сохраняй художественные требования MASTER_RULES.md; Lean меняет порядок чтения, не качество. Владелец единственный утверждает канон и выпуск.
- Не публиковать, не тратить деньги, не менять модели, правила, архитектуру или другие репозитории без разрешения. Секреты вне Git.
## Экономия
- Только запрошенная задача; минимальный необходимый код и целевые тесты. Не создавать новые версии студии, интерфейсы, тестовые видео, не скачивать модели.
- По умолчанию один исполнитель; независимая проверка обязательна там, где требует регламент, без массового запуска агентов.
- Один образец до массовой генерации. Не более двух попыток на элемент за задачу; затем блокер и согласование. Не повторять удачные результаты.
- Не запускать анимацию, озвучку, массовое производство до отдельного разрешения.
- Отчёт до 10 строк: результат, проверка, пути/версии, блокер, следующий шаг. Не скрывать ошибки; подробности только при необходимости.
- CURRENT_STATE.md до 50 строк, обновлять при изменении состояния; PROJECT_MEMORY.md и PROGRESS.md сохранять как историю, дополнять существенными решениями/проверками без повторного пересказа.
- Перед сдачей проверить применимые требования, фактические файлы и статус. Не заявлять успех без проверки.
